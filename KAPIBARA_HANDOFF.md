# Kapibara AI — справка для нового чата

**Назначение:** это рабочая памятка для ChatGPT, продолжающего разработку сайта Kapibara AI с пользователем. Перед любой правкой проверь актуальные файлы GitHub: памятка — ориентир, а не замена проверки.

## Проект и ссылки

- Проект: **Kapibara AI**, небольшая дружелюбная студия креативного дизайна. В перспективе пользователь хочет брать заказы на баннеры, афиши, аватары, карточки товаров и простые сайты-визитки.
- Сайт GitHub Pages: https://kiberdoker-pixel.github.io/markoobraznye-nsk/
- Репозиторий: **kiberdoker-pixel/markoobraznye-nsk**, основная ветка **main**. Историческое название репозитория осталось от другого проекта — оно не означает, что сайт надо переделывать в автомобильный.
- Контакт для клиентов: https://t.me/KapibaraAI
- Возможный домен `kapibaraai.ru` лишь обсуждался, считать его покупку/подключение не подтверждёнными.
- Пользователь параллельно ведёт разработку **другого приложения в другом чате**. **Не смешивать** задачи, код, решения и договорённости двух проектов.

## Файлы сайта

- `index.html` — главная.
- `portfolio.html` — портфолио.
- `assets/style.css` — оформление и фоновые изображения плиток.
- `assets/app.js` — интерактивность.
- `assets/kapibara-logo.webp` — **утверждённый фирменный логотип**, капибара в наушниках/худи у ноутбука. Без явной просьбы не менять.
- `assets/kapibara-cursor.webp` — декоративный курсор.

## Утверждённый стиль

- Тёмный, современный, дружелюбный стиль, индивидуальные цветовые акценты шести плиток, мультяшные детализированные капибары и умеренные анимации.
- На главной утверждён текстовый блок: **«Без пафоса. С душой.»** выше, **«Давай знакомиться»** ниже. Не переставлять без просьбы.
- Сохранять работающие ссылки, адаптивность, hover-эффекты, анимации, фирменный стиль.
- Пользователь крайне не любит, когда вместе с точечной правкой самовольно меняются ранее согласованные элементы.

В `assets/style.css` фоновые изображения прописаны так:

| № | Направление | CSS-класс | Файл изображения |
|---|---|---|---|
| 1 | DESIGN — Рекламные баннеры | `tile-coral` | `assets/tile-1-detailed.webp` |
| 2 | PRINT — Афиши и постеры | `tile-peach` | `assets/tile-2-detailed.webp` |
| 3 | SOCIAL — Аватарки и обложки | `tile-purple` | `assets/tile-3.webp` |
| 4 | WEB — Сайты-визитки | `tile-green` | `assets/tile-4.webp` |
| 5 | PRODUCTS — Карточки товаров | `tile-blue` | `assets/tile-5.webp` |
| 6 | LET'S TALK — Есть своя идея? | `tile-contact` | `assets/tile-6.webp` |

**Важно:** последняя путаница касалась **плиток 1 и 2, а не 5 и 6**. Пользователь прислал три скриншота (сайт, неправильные плитки, эталонные плитки); эталон для №1 и №2 — **детализированные картинки**: №1 капибара в тёмном худи с баннером BANNER; №2 капибара в берете с автомобильным постером POSTER. В GitHub CSS уже ссылается на `tile-1-detailed.webp` и `tile-2-detailed.webp`; все шесть файлов картинок найдены в каталоге `assets`.

Для №1 и №2 CSS скрывает HTML-дубли текстов и стрелок через opacity:0, поскольку **на самих изображениях уже есть надписи**. Для №3–6 используются фоновые изображения и видимый HTML-текст. Эти особенности не менять без запроса пользователя.

Факт наличия файлов и CSS проверен через подключённый GitHub. **Отображение опубликованной версии на телефоне пользователя отдельно не подтверждено** (кеш/время GitHub Pages возможны). Если пользователь покажет новый скриншот, в первую очередь сверяй его с текущим кодом и ожидаемым результатом.

## Как работать в новом чате

1. Общаться с пользователем по-русски, тепло и по-дружески; обращение «брат» уместно. Если человек хочет просто поговорить, **не запускать инструменты и не изменять сайт**.
2. При просьбе о правке **коротко повторить точный объём**: какие номера плиток, что заменить, чего не касаться.
3. Прежде чем править, через подключённый GitHub читать актуальные `index.html`, `assets/style.css` и необходимые ресурсы. Не доверять старым предположениям о состоянии проекта.
4. **Менять только запрошенное**. Не генерировать новые варианты вместо уже утверждённых, не добавлять несогласованные улучшения.
5. Пользователь рассчитывает, что ChatGPT **сам вносит правки в GitHub**. Не отправлять его без необходимости в Codex или ручной редактор, если доступен рабочий GitHub-коннектор.
6. После изменения проверять коммит, содержание файлов и ссылки. Говорить «на GitHub сохранено» только после подтверждения. Не утверждать, что опубликованная страница обновилась и работает, если это не проверено.
7. Если инструкция противоречива, не угадывать; задать **один короткий уточняющий вопрос**. Если пользователь скажет «Брат, ты сбился», остановить действия, свериться с задачей и состоянием GitHub, кратко объяснить расхождение.
8. После завершения **только утверждённых** изменений при необходимости обновлять эту памятку.
